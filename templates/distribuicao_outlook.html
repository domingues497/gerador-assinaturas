Distribuição remota para Outlook

Complemento do Gerador de Assinaturas existente. Não altera os cadastros e modelos atuais.

{{ 'Entra ID configurado' if entra_configurado else 'Configuração pendente' }}
Como funcionará: quando o usuário criar uma mensagem, responder ou encaminhar no Outlook clássico ou no novo Outlook, o suplemento validará sua identidade Microsoft 365 e buscará a assinatura atual no gerador. A alteração de um modelo ou dos dados do colaborador será refletida na próxima composição.

1. Preparar o Microsoft Entra ID

  1. Registre um aplicativo no Microsoft Entra ID para o suplemento.
  2. Configure o URI de identificação da API como api://<CLIENT_ID> ou outro URI validado pela política do tenant.
  3. Exponha o escopo delegado access_as_user e autorize o cliente Office conforme a documentação de SSO para suplementos do Outlook.
  4. Conceda o consentimento administrativo necessário e confirme que o token emitido tem o emissor, tenant e audiência configurados no servidor.

2. Configurar o executável no computador da TI

Defina estas variáveis de ambiente para o processo que inicia o gerador. Depois, reinicie o executável.

GERADOR_ENTRA_TENANT_ID={{ tenant_id or 'SEU_TENANT_ID' }}
GERADOR_ENTRA_CLIENT_ID={{ client_id or 'CLIENT_ID_DO_APP' }}
GERADOR_ENTRA_AUDIENCE={{ audience or 'AUDIENCIA_EXATA_DO_ACCESS_TOKEN' }}

Se o token usar um emissor diferente do padrão v2, configure também GERADOR_ENTRA_ISSUER. A audiência deve corresponder ao claim aud do access token recebido, não ser adivinhada.

3. Hospedar com HTTPS

O suplemento exige URLs HTTPS acessíveis pelos computadores dos funcionários. O executável atual usa o servidor de desenvolvimento do Flask e, por padrão, escuta somente em 127.0.0.1. Não publique diretamente esse servidor na Internet.

Use um proxy HTTPS/servidor de produção com regras de allowlist: exponha somente os recursos do suplemento e {{ api_url }}; bloqueie as páginas administrativas do gerador para acesso externo. O computador da TI precisará permanecer ligado e o serviço disponível, ou a API deverá ser movida posteriormente para um servidor de produção.

4. Publicar o suplemento

  1. Configure o arquivo outlook_addin/manifest.xml.template com a URL HTTPS pública, Client ID e URI de recurso do aplicativo.
  2. Hospede autorun.html e autorun.js na mesma origem HTTPS da API.
  3. Valide o manifesto e faça upload em Microsoft 365 Admin Center → Configurações → Aplicativos integrados.
  4. Implante primeiro para um grupo piloto com Outlook clássico e novo Outlook.
Esta tela é um guia de implantação. A publicação só deve ser feita depois de configurar Entra ID, HTTPS, proxy com allowlist e validar o manifesto no tenant.
